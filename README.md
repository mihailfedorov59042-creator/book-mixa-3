# «Полка XVII–XVIII веков» — устанавливаемое PWA

Это исходный проект библиотеки с добавленными возможностями установки на Android и компьютер, автономного чтения и безопасных обновлений. **Тексты, изображения, заметки, прогресс чтения и оригинальный интерфейс сохранены.**

## Быстрый запуск

1. Распакуйте архив, сохранив папку `data/` рядом с `index.html`.
2. Для проверки на компьютере откройте терминал внутри папки проекта и выполните:
   ```bash
   python3 -m http.server 8000
   ```
3. Откройте **http://localhost:8000/** (не `file:///...`). Подождите, пока на странице появится «Библиотека доступна без интернета».
4. Отключите интернет и перезагрузите страницу: книги должны открываться даже офлайн.

**Для установки на телефон необходим общедоступный адрес с HTTPS.** Установить PWA напрямую из ZIP или по `file://` нельзя.

## Публикация через GitHub Pages и автоматические обновления

1. Создайте репозиторий GitHub и загрузите в его **корень** всё содержимое этой папки, включая скрытую `.github/` и файл `.nojekyll`. Если библиотека предназначена для всех читателей, выберите доступность репозитория с учётом прав на тексты и переводы.
2. В настройках репозитория откройте **Settings → Pages → Build and deployment** и выберите **GitHub Actions**.
3. При каждой отправке изменений в ветку `main` готовый workflow `.github/workflows/deploy.yml` автоматически:
   - запустит `python3 tools/build_pwa.py`;
   - пересчитает отпечаток всех файлов, включая произведения;
   - создаст новую согласованную версию `sw.js`;
   - опубликует PWA на GitHub Pages.
4. Откройте опубликованный HTTPS-адрес и установите приложение через браузер. На Android в Chrome выберите «Установить приложение» или меню «Добавить на главный экран». В Chrome/Edge на ПК используйте команду установки в адресной строке/меню.
5. Для следующих выпусков достаточно заменить/изменить файлы проекта и отправить их в `main`: публикация и загрузка обновления у читателей выполняются автоматически, когда появится соединение с интернетом. Если приложение открыто, после загрузки новой версии появится кнопка **«Обновить»**. Если закрыто, новая версия активируется при следующем открытии после проверки обновлений.

Можно также разместить папку на любом статическом хостинге с HTTPS. При таком развёртывании запускайте скрипт сборки перед публикацией, чтобы сформировать актуальный `sw.js`.

## Как выпускать обновления

Изменяйте исходный `index.html`, любые файлы `data/*.js`, `pwa.js`, `pwa.css`, иконки и `manifest.webmanifest`.

```bash
python3 tools/build_pwa.py
```

**Важно:** `sw.js` генерируется автоматически; редактировать его вручную не нужно. Если нужно изменить логику офлайн-кэша, исправляйте `tools/sw.template.js`. Скрипт также обновляет параметр версии в ссылках на все `data/*.js`. Это исключает смешивание старых и новых произведений и сценариев. Сборка детерминирована: одинаковые исходники дают один и тот же идентификатор версии.

Сервисный работник сохраняет всю библиотеку целиком (около 17 МБ) для чтения без сети. Новая версия сначала кэшируется целиком. Если скачивание прервётся, читатель продолжит пользоваться предыдущей версией. После успешной загрузки обновление предлагается на странице; оно не прерывает чтение самостоятельно.

## Заметки и сохранённый прогресс

Пользовательские данные сохраняются в `localStorage` браузера под исходным ключом `polka-reader-v1`. Service Worker удаляет **только старые кэши файлов приложения**. Он не изменяет `localStorage` и не очищает заметки.

Данные **привязаны к адресу (origin)**. Прогресс не синхронизируется между устройствами. Заметки можно перенести вручную через JSON-файл. Автоматическая инициализация прежней облачной интеграции отключена: приложение не отправляет заметки на серверы. При очистке данных сайта в браузере локальные заметки и локальная страховочная копия удаляются, поэтому храните скачанный JSON отдельно.

### Перенос заметок между Android и Windows

1. На исходном устройстве откройте раздел «Книги» и нажмите **«Выгрузить заметки»** рядом с «Проверить обновления». Сохраните файл `polka-notes-<дата>.json` в загрузках браузера или выбранной папке.
2. Перенесите этот файл на другое устройство удобным вам способом, например USB-кабелем. Само приложение никуда его не отправляет.
3. На другом устройстве нажмите **«Загрузить заметки»** и выберите JSON-файл системным диалогом.
4. Проверьте количество заметок и выберите режим:
   - **Объединить** (по умолчанию) — сохранить текущие заметки и добавить заметки из файла. Если один идентификатор имеет разное содержимое на двух устройствах, обе версии останутся отдельными заметками. Повторная загрузка того же файла не создаёт дубликатов.
   - **Заменить** — заменить только список заметок данными из файла. Приложение отдельно просит подтвердить замену, включая очистку списка при загрузке пустой копии.
5. Нажмите **«Создать копию и загрузить»** и подтвердите действие. Сначала приложение сохраняет JSON-копию текущих заметок на этом устройстве под отдельным ключом `polka-reader-v1-notes-backup`, затем записывает результат. Если создание копии или сохранение не удалось, текущие заметки не меняются.

После импорта появляется кнопка **«Скачать копию до загрузки»**. Она остаётся доступной после перезапуска PWA. Чтобы вернуть предыдущие заметки, скачайте эту копию и загрузите её с режимом «Заменить». Копия содержит состояние перед последним импортом и обновляется при следующем импорте. Для длительного хранения скачайте её в отдельный файл.

Кнопки используют обычные возможности Chrome/Edge на Windows и Chrome на Android: скачивание `Blob` и системный выбор файла. Импорт и экспорт доступны и в установленном PWA, и в браузере, в том числе **без интернета** после первой загрузки приложения. Несохранённую заметку нужно сначала сохранить или закрыть. Изменение данных в другом окне после выбора файла отменяет импорт: выберите файл заново.

Формат: объект с `format: "polka-notes"`, `version: 1`, датой `exportedAt` и массивом `notes`. Переносятся текст, цитата, книга, диапазон выделения, подпись, позиция и даты каждой заметки. Прогресс чтения, закладки, настройки, рисунки и сохранённые комментарии на целевом устройстве не заменяются. Книги и изображения в резервную копию не входят. Поддерживаются файлы до 5 МБ и 10 000 заметок. Неверный JSON, неподдерживаемая версия, неизвестная книга, повторяющиеся/небезопасные идентификаторы и неправильные типы полей отклоняются до записи данных.

### Проверки перед публикацией

```bash
npm ci
npx playwright install --with-deps chromium
npm test
```

В набор входят модульные проверки формата, конфликтов, резервного восстановления, переполнения хранилища и сохранности остальных данных, а также браузерные проверки в настольном режиме Windows и сенсорном режиме Android. Браузерный набор проверяет реальный Service Worker: обновление с исходной версии `99f7fd9`, прерванное скачивание обновления, активацию после подтверждения, импорт/экспорт и чтение офлайн. Данные тестов вымышленные. Эмуляция браузера не заменяет проверку системных окон на физических устройствах.

GitHub Actions запускает сборку и оба набора тестов перед публикацией, затем собирает в `_site/` только файлы приложения, книги и иконки. Зависимости тестов в сайт не попадают. Источник Pages должен быть **GitHub Actions**, чтобы исключить параллельную публикацию из ветки в обход тестов. Ошибка тестов останавливает публикацию workflow. Для локальной проверки с установленным системным Chromium можно выполнить `POLKA_CHROMIUM_PATH=/usr/bin/chromium npm test`.

## Структура

- `index.html` — существующий интерфейс библиотеки и сценарии чтения;
- `data/*.js` — оригинальные тексты и иллюстрации;
- `manifest.webmanifest` — название, цвета, иконки, запуск PWA;
- `icons/` — иконки приложения;
- `pwa.js`, `pwa.css` — установка, индикатор состояния и управление обновлениями;
- `notes-transfer.js` — проверка JSON, объединение, резервные копии и локальный импорт/экспорт;
- `tests/`, `package.json`, `package-lock.json` — проверки логики и браузерные сценарии;
- `sw.js` — автогенерируемый сервисный работник и кэш всех книг;
- `tools/build_pwa.py` — сборка версии и пересчёт контрольной суммы;
- `tools/sw.template.js` — исходник офлайн-работника;
- `.github/workflows/deploy.yml` — автоматическая публикация на GitHub Pages.

## Ограничения

- Браузер и ОС решают, показывать ли системную кнопку установки. На iPhone/iPad обычно используется «Поделиться» → «На экран Домой».
- Для первой установки и первоначальной загрузки всех книг нужен интернет. Первый запуск может потребовать загрузки примерно 17 МБ.
- Онлайн-шрифты Google не входят в кэш. При работе офлайн тексты остаются доступны, но начертание отдельных шрифтов может отличаться из-за системных замен.
- Публикуя библиотеку в открытом доступе, отдельно проверьте право размещать переводы, комментарии, исследования и иллюстрации. Общедоступность оригинала произведения не всегда распространяется на перевод.
