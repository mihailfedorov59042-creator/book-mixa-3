# «Полка XVII–XVIII веков» — устанавливаемое PWA

Это исходный проект библиотеки с добавленными возможностями установки на Android и компьютер, автономного чтения и безопасных обновлений. **Тексты, изображения, заметки, прогресс чтения и оригинальный интерфейс сохранены.**

## Полки и настройки

Для новых схем и доработки существующих используйте [инструкцию по созданию схем](docs/SCHEME-GUIDE.md). Она описывает проверку содержания, четыре режима, оформление по образцу «Федры», рисование, сохранность данных, испытания и публикацию; в конце есть готовое задание для следующей работы.

Главный экран предлагает выбор полки: XVII–XVIII века, театр Гоцци, XX век, Еврипид и теория. Книги открываются на отдельном экране выбранной полки. Кнопка «Все полки» возвращает к выбору; ссылки `#shelf/theory` и другие полки можно сохранять в закладки. Возврат из книги ведёт на её полку. Поиск по всем книгам и продолжение чтения доступны на главном экране.

Шестерёнка открывает настройки на главной странице, в заметках, родословных и читалке. Здесь находятся заставки, обновления PWA, установка приложения и перенос заметок через JSON. В читалке также доступны размер текста и прежние настройки чтения. Автоматическая облачная синхронизация не подключена; заметки остаются на устройстве.

## Быстрый запуск

1. Распакуйте архив, сохранив папку `data/` рядом с `index.html`.
2. Для проверки на компьютере откройте терминал внутри папки проекта и выполните:
   ```bash
   python3 -m http.server 8000
   ```
3. Откройте **http://localhost:8000/** (не `file:///...`). Нажмите шестерёнку и подождите сообщения «Библиотека доступна без интернета».
4. Отключите интернет и перезагрузите страницу: книги должны открываться даже офлайн.

**Для установки на телефон необходим общедоступный адрес с HTTPS.** Установить PWA напрямую из ZIP или по `file://` нельзя.

## Публикация через GitHub Pages и автоматические обновления

1. Создайте репозиторий GitHub и загрузите в его **корень** всё содержимое этой папки, включая скрытую `.github/` и файл `.nojekyll`. Если библиотека предназначена для всех читателей, выберите доступность репозитория с учётом прав на тексты и переводы.
2. В настройках репозитория откройте **Settings → Pages → Build and deployment** и выберите **GitHub Actions**.
3. При каждой отправке изменений в ветку `main` готовый workflow `.github/workflows/deploy.yml` автоматически:
   - запустит `python3 tools/build_pwa.py`;
   - пересчитает отпечаток всех файлов, включая произведения;
   - создаст новую согласованную версию `sw.js`;
   - опубликует PWA на GitHub Pages.
4. Откройте опубликованный HTTPS-адрес и установите приложение через браузер. На Android в Chrome выберите «Установить приложение» или меню «Добавить на главный экран». В Chrome/Edge на ПК используйте команду установки в адресной строке/меню.
5. Для следующих выпусков достаточно заменить/изменить файлы проекта и отправить их в `main`: публикация и загрузка обновления у читателей выполняются автоматически, когда появится соединение с интернетом. Если приложение открыто, после загрузки новой версии появится кнопка **«Обновить»**. Если закрыто, новая версия активируется при следующем открытии после проверки обновлений.

Можно также разместить папку на любом статическом хостинге с HTTPS. При таком развёртывании запускайте скрипт сборки перед публикацией, чтобы сформировать актуальный `sw.js`.

## Как выпускать обновления

Изменяйте исходный `index.html`, любые файлы `data/*.js`, `pwa.js`, `pwa.css`, иконки и `manifest.webmanifest`.

```bash
python3 tools/build_pwa.py
```

**Важно:** `sw.js` генерируется автоматически; редактировать его вручную не нужно. Если нужно изменить логику офлайн-кэша, исправляйте `tools/sw.template.js`. Скрипт также обновляет параметр версии в ссылках на все `data/*.js`. Это исключает смешивание старых и новых произведений и сценариев. Сборка детерминирована: одинаковые исходники дают один и тот же идентификатор версии.

Сервисный работник сохраняет всю библиотеку целиком (около 19 МБ) для чтения без сети. Новая версия сначала кэшируется целиком. Если скачивание прервётся, читатель продолжит пользоваться предыдущей версией. После успешной загрузки обновление предлагается на странице; оно не прерывает чтение самостоятельно.

## Ролан Барт: «Избранные работы. Семиотика. Поэтика»

В раздел «Теория» добавлен сборник из присланного FB2: М.: Прогресс, 1989; составление, общая редакция и вступительная статья Г. К. Косикова. Сохранены все 1315 непустых абзацев исходного файла в исходном порядке, 34 заголовка, выделения, надстрочные/подстрочные знаки, семиологическая схема и обложка. Оглавление, поиск, заметки, прогресс и файловый перенос заметок работают через общие механизмы библиотеки. Книга и встроенная обложка входят в офлайн-кэш PWA.

Воспроизводимая конвертация без внешних зависимостей:

```bash
python3 tools/import_fb2.py source.fb2 --id barthes --output data/b-barthes.js
python3 tools/build_pwa.py
```

Контрольные суммы исходного FB2 и последовательности абзацев находятся в поле `source` файла книги. Тесты сверяют сохранность текста с контрольной суммой присланного источника, оглавление, схему и обложку; браузерные сценарии проверяют чтение и заметки на компьютере и Android, в том числе офлайн.

## Заметки и сохранённый прогресс

Пользовательские данные сохраняются в `localStorage` браузера под исходным ключом `polka-reader-v1`. Service Worker удаляет **только старые кэши файлов приложения**. Он не изменяет `localStorage` и не очищает заметки.

Данные **привязаны к адресу (origin)**. Прогресс не синхронизируется между устройствами. Заметки можно перенести вручную через JSON-файл. Автоматическая инициализация прежней облачной интеграции отключена: приложение не отправляет заметки на серверы. При очистке данных сайта в браузере локальные заметки и локальная страховочная копия удаляются, поэтому храните скачанный JSON отдельно.

### Папка для JSON-копий

В настройках можно выбрать и запомнить папку выгрузки. Поддерживающий File System Access API браузер (например, Chrome/Edge на Windows) запоминает доступ к папке в IndexedDB этого устройства. Экспорт заметок и выгрузка страховочной копии используют эту папку; успешное сообщение появляется только после завершения записи. После перезапуска браузер может снова запросить разрешение. Отмена выбора, запрет доступа или ошибка записи не изменяют заметки. Кнопка «Сохранять в загрузки браузера» сбрасывает привязку, сохраняя ранее созданные файлы.

В браузерах без `showDirectoryPicker`, включая многие браузеры Android, закрепить папку средствами PWA невозможно. Здесь доступны обычные загрузки, а место сохранения определяется настройками браузера/системным диалогом. Интерфейс показывает это ограничение. Выбор папки не включает автоматическую синхронизацию и не переносит рабочее хранилище заметок из приложения.

### Перенос заметок между Android и Windows

1. На исходном устройстве откройте настройки шестерёнкой и нажмите **«Выгрузить заметки»**. Сохраните файл `polka-notes-<дата>.json` в загрузках браузера или выбранной папке.
2. Перенесите этот файл на другое устройство удобным вам способом, например USB-кабелем. Само приложение никуда его не отправляет.
3. На другом устройстве нажмите **«Загрузить заметки»** и выберите JSON-файл системным диалогом.
4. Проверьте число заметок, оценок и отметок о прочтении. Выберите режим загрузки.
   - **Объединить** (по умолчанию) — сохранить текущие заметки и добавить заметки из файла. Если один идентификатор имеет разное содержимое на двух устройствах, обе версии останутся отдельными заметками. Повторная загрузка того же файла не создаёт дубликатов.
   - **Заменить** — восстановить из файла заметки, оценки цитат и отметки о прочтении. Для старого файла версии 1 заменяется только список заметок. Приложение отдельно просит подтвердить замену, включая очистку списка при загрузке пустой копии.
5. Нажмите **«Создать копию и загрузить»** и подтвердите действие. Сначала приложение сохраняет JSON-копию текущих заметок, оценок и отметок о прочтении на этом устройстве под отдельным ключом `polka-reader-v1-notes-backup`, затем записывает результат. Если создание копии или сохранение не удалось, текущие заметки не меняются.

После импорта в настройках появляется кнопка **«Скачать копию до загрузки»**. Она остаётся доступной после перезапуска PWA. Чтобы вернуть предыдущие заметки, скачайте эту копию и загрузите её с режимом «Заменить». Копия содержит состояние перед последним импортом и обновляется при следующем импорте. Для длительного хранения скачайте её в отдельный файл.

Кнопки используют обычные возможности Chrome/Edge на Windows и Chrome на Android: скачивание `Blob` и системный выбор файла. Импорт и экспорт доступны и в установленном PWA, и в браузере, в том числе **без интернета** после первой загрузки приложения. Несохранённую заметку нужно сначала сохранить или закрыть. Изменение данных в другом окне после выбора файла отменяет импорт: выберите файл заново.

Копия в формате `polka-notes` версии 2 содержит дату выгрузки, заметки (`notes`), оценки цитат (`quoteRatings`) и отметки о прочтении книг (`read`). Оценка переносится и для цитаты, которую читатель не добавил в заметки. При объединении для каждой оценки или отметки используется более свежее изменение, в том числе снятие. При совпадении дат остаётся выбор на устройстве. При замене восстанавливаются все три раздела. Файл версии 1 восстанавливает только заметки. Позиция чтения, закладки и настройки сохраняются на устройстве. Поддерживаются файлы до 5 МБ и 10 000 заметок. Неверный JSON, неподдерживаемая версия, неизвестная книга, повторяющиеся/небезопасные идентификаторы и неправильные типы полей отклоняются до записи данных.

### Проверки перед публикацией

```bash
npm ci
npx playwright install --with-deps chromium
npm test
```

В набор входят модульные проверки формата, конфликтов, резервного восстановления, переполнения хранилища и сохранности остальных данных, а также браузерные проверки в настольном режиме Windows и сенсорном режиме Android. Браузерный набор проверяет реальный Service Worker: обновление с исходной версии `99f7fd9`, прерванное скачивание обновления, активацию после подтверждения, импорт/экспорт и чтение офлайн. Данные тестов вымышленные. Эмуляция браузера не заменяет проверку системных окон на физических устройствах.

GitHub Actions запускает сборку и оба набора тестов перед публикацией, используя предустановленный Google Chrome Ubuntu-раннера без дополнительного скачивания браузера. Затем workflow собирает в `_site/` только файлы приложения, книги и иконки. Зависимости тестов в сайт не попадают. Источник Pages должен быть **GitHub Actions**, чтобы исключить параллельную публикацию из ветки в обход тестов. Ошибка тестов останавливает публикацию workflow. Для локальной проверки с установленным системным Chromium можно выполнить `POLKA_CHROMIUM_PATH=/usr/bin/chromium npm test`.

## Структура

- `index.html` — существующий интерфейс библиотеки и сценарии чтения;
- `data/*.js` — оригинальные тексты и иллюстрации;
- `manifest.webmanifest` — название, цвета, иконки, запуск PWA;
- `icons/` — иконки приложения;
- `pwa.js`, `pwa.css` — установка, индикатор состояния и управление обновлениями;
- `notes-transfer.js` — проверка JSON, объединение, резервные копии и локальный импорт/экспорт;
- `tests/`, `package.json`, `package-lock.json` — проверки логики и браузерные сценарии;
- `sw.js` — автогенерируемый сервисный работник и кэш всех книг;
- `tools/build_pwa.py` — сборка версии и пересчёт контрольной суммы;
- `tools/sw.template.js` — исходник офлайн-работника;
- `.github/workflows/deploy.yml` — автоматическая публикация на GitHub Pages.

## Ограничения

- Браузер и ОС решают, показывать ли системную кнопку установки. На iPhone/iPad обычно используется «Поделиться» → «На экран Домой».
- Для первой установки и первоначальной загрузки всех книг нужен интернет. Первый запуск может потребовать загрузки примерно 19 МБ.
- Онлайн-шрифты Google не входят в кэш. При работе офлайн тексты остаются доступны, но начертание отдельных шрифтов может отличаться из-за системных замен.
- Публикуя библиотеку в открытом доступе, отдельно проверьте право размещать переводы, комментарии, исследования и иллюстрации. Общедоступность оригинала произведения не всегда распространяется на перевод.

## Раздельная установка PWA

У этого приложения собственный `id` с путём репозитория. Указывать `id: "./"` нельзя: относительный идентификатор PWA разрешается от корня origin, и приложения одного аккаунта GitHub Pages получают одинаковую идентичность. `start_url` и `scope` остаются в папке приложения. Данные браузера не очищаются.

Если Android уже объединил старые установки, серверное обновление не гарантирует автоматического разделения существующих ярлыков. Сначала сохраните резервную копию важных данных, затем откройте точные адреса `/book-mixa-3/` и `/SSL/` в Chrome и установите каждое приложение отдельно. Удалять данные всего домена GitHub Pages не нужно. Старый объединённый ярлык удаляйте только после проверки новых установок и резервных копий.

## Полка «Пушкин»

[Открыть полку](https://mihailfedorov59042-creator.github.io/book-mixa-3/#shelf/pushkin). В ней 16 книг по пятому тому академического издания «Наука» (Ленинград, 1978): «Евгений Онегин», семь драматических произведений и восемь отрывков и набросков. У каждой книги собственные оглавление, прогресс, схема и хроники героев. Чтобы увидеть уже прочитанные события, откройте персонажа. Кнопка «Полная характеристика» раскрывает дальнейшие события, а нажатие на этап ведёт к его месту в тексте.

Входной FB2 имеет SHA-256 `c7124d392869e95efc8271ff40b8e134b113e5865ac0afec3cfb6d126c016c15`. Для воспроизведения данных выполните `python tools/import_pushkin.py путь/к/тому.fb2`, затем `python tools/build_pwa.py`. Импортёр сохраняет внутренние ссылки, сноски, авторские приложения, ранние редакции и издательский комментарий. При сборке он сверяет последовательность строк и абзацев основных текстов с FB2. Смысловые этапы хроник и отношения персонажей редактируются в `tools/pushkin-characters.json`. [Происхождение иллюстраций](docs/PUSHKIN-ART.md).

## Гомер

[Полка Гомера](https://mihailfedorov59042-creator.github.io/book-mixa-3/#shelf/homer) содержит две книги в переводах Н. И. Гнедича и В. А. Жуковского. У каждой свои оглавление, прогресс, примечания и схема. При уменьшении масштаба видны сначала 6, затем 13 и наконец 25 персонажей. Кнопки в схеме позволяют закрепить уровень. В карточке персонажа можно открыть хронику и перейти к соответствующему стиху.

[Словари двух поэм](data/homer-dictionary.html) собраны в одном самостоятельном HTML-файле. На титульнике каждой поэмы есть ссылка на её раздел. Обложки взяты из самих FB2. Источники иллюстраций указаны под изображениями в читалке. [Композиции Джона Флаксмана](https://www.gutenberg.org/ebooks/6130) · [Иллюстрации Вилли Погани](https://www.gutenberg.org/ebooks/16867)

Для повторной сборки передайте оба исходных FB2 команде `python tools/import_homer.py "Илиада.fb2" "Одиссея.fb2"`, затем выполните `python tools/build_pwa.py`. Этапы хроник хранятся в `tools/homer-chronicles.txt`. При импорте каждая цитата-якорь должна встретиться ровно один раз в указанной песни.
